## 1. The method — a controlled reproduction {#reproduced}

This bullet makes a *causal* claim — that a documented segmentation failure was caused by the **pipeline**, not by an inadequate network. A causal claim is only as good as the experiment that licenses it, so every phrase below is really a defense of experimental design. The three phrases unpack in order: *what* was reproduced (a pipeline's **behaviour**, honestly sourced and faithfully — not weakly — reproduced), *how* it was compared (a **controlled** A/B where exactly one thing moves), and *why* the comparison is attributable (a **byte-identical** network is what turns a difference into a cause).

### "Reproduced … a defective … pipeline"

**Claim.** *"Reproduced a defective glioma-segmentation pipeline."* The object of the verb is the **data pipeline's behaviour** — its label handling, normalisation, sampling, loss, and checkpoint-selection — **not** a set of trained weights. No original weights were reused; the pathology was re-implemented in PyTorch/MONAI and shown to reproduce.

**What it means — honest provenance first.** The reference was a Colab export, `unet_cc.py`, whose header literally reads *"Copy of Untitled7.ipynb … Automatically generated by Colab."* That header is itself a tell: the file is a copy of an unnamed shared notebook, and it carries a BraTS-2020-era label remap forward onto 2024 data — the remap is defect **D7** (it merges the resection cavity into enhancing tumour, collapsing the problem to 4 classes). The file has **no author, no README, and no LICENSE**. It was **not redistributed**; only its *behaviour* was reproduced. This matters for the honesty of the claim: "reproduced" means *reproduced a documented pathology from re-written code*, not *forked someone's repo and reran it*.

**Evidence — this is a faithful reproduction, not a strawman.** A reproduction is only defensible if it recreates the *documented pathology* rather than an easy-to-beat caricature. Track A does exactly that. On validation it reaches a voxel accuracy of **0.991** while its mean foreground Dice is only **0.320**, and the rarest class, NETC, sits at Dice **0.009** — a near-total miss. That accuracy-vs-Dice divergence *is* the pathology: a model that predicts "background" almost everywhere scores 99% of voxels correct while segmenting essentially nothing. The "best" checkpoint was selected at epochs **18–22** on validation accuracy, which is defect **D4** operating as designed.

![Track A pathology: validation voxel accuracy 0.991 coexisting with mean-fg Dice 0.320 and NETC Dice 0.009 — the accuracy-vs-Dice divergence that defines a faithful reproduction of the failure.](reports/figures/dossier/track_a_fidelity.png)

!!! gotcha "Watch out — every Dice here is voxel-wise"
    These are **voxel-wise** Dice scores, *not* the BraTS lesion-wise challenge metric. They are internally consistent for an A/B comparison but are **not comparable to leaderboards**. Throughout this bullet, the load-bearing quantity is the *contrast* between the arms, never the absolute level.

**Verify.** The fidelity numbers (val acc 0.991, val mean-fg 0.320, NETC 0.009, checkpoint epochs 18–22) are plotted in `reports/figures/dossier/track_a_fidelity.png` and recomputed in `scripts/compute_dossier_facts.py`. The provenance is quotable from the reference file header — `unet_cc.py` opens with *"Copy of Untitled7.ipynb … Automatically generated by Colab"* — though that file is **local-only** (it has no license and was purged from the public repository, so it is not redistributed). The nine defects and their exact fixes are catalogued in §20 of the Explainer.

!!! example "Interview question"
    **"Isn't Track A a strawman you built specifically so it would lose?"**
    No — and it is checkable. Each defect Track A carries is traced to a real line of the reference code (D1 = a `cv2.resize` bilinear interpolation on the *label* volume; D4 = checkpoint selection on accuracy; D5 = global-max normalisation; and so on — see §20). Track A reproduces the *documented* pathology: 99.1% voxel accuracy with 0.320 mean-fg Dice, the classic "predicts background" collapse. If anything I was **more generous** than the reference, not less: the reference is a **4-class** contract that merges the resection cavity into enhancing tumour (defect D7), which quietly deletes one hard class from the scoring. I kept the full **5-class** problem, so Track A is graded on strictly harder terms than the original it reproduces.

!!! example "Interview question"
    **"Whose code did you reproduce, and did you have the right to?"**
    It was an unattributed Colab export (`unet_cc.py`, header: *"Copy of Untitled7.ipynb … Automatically generated by Colab"*) — itself a copy of an unnamed shared notebook, with no author, no README, and no LICENSE. Because there is no license and no clear owner, I did **not** redistribute it and reused **no original weights**. What I reproduced is its *behaviour*, re-implemented from scratch in PyTorch/MONAI, and I document the provenance honestly rather than claiming authorship of the pipeline it came from.

### "controlled A/B"

**Claim.** *"as a controlled A/B."* A controlled experiment is one in which **exactly one thing changes** between the two arms and everything else is held fixed, so that any measured difference can be assigned to that one thing.

**What it means.** Here the single moving part is the **data-and-training pipeline** — bundled as three coupled changes that always travel together: the **data pipeline** (label resampling, normalisation, patch sampling), the **loss**, and the **checkpoint-selection rule**. Track A carries the defective versions (it reproduces **D1, D3, D4, D5, D6, D9**); Track B carries the fixes. Everything an experimenter would otherwise be tempted to also improve is **frozen**: the network **architecture** (byte-identical, see below), the **data split** (the same fixed 490/105/105, seed 42), and the **seeds protocol** (both arms trained over the same 3 seeds). Two defects are deliberately outside the A/B to keep it clean: **D8** (the *reference* had no normalization layers; the MONAI network uses instance normalization on **both** tracks) and **D2** (a Dice metric shape/index bug, *fixed on both* so the yardstick is trustworthy) are corrected identically in both arms — so neither is part of the comparison. **D7** (the 4→5-class contract) is enforced on both so both arms are scored on the same 5 classes.

**Evidence — the defect ladder.** The set of changes is not an unordered pile; it is a ladder from raw pathology to corrected pipeline, each rung a named defect with a named fix. Making the bundle explicit is what makes the A/B *controlled* — an interviewer can see that nothing improved silently.

![The defect ladder: each rung is one named pipeline defect (D1–D9) with its fix; Track A carries D1/D3/D4/D5/D6/D9, while D2 (metric), D7 (5-class contract) and D8 (instance norm) are corrected identically on both tracks — outside the A/B.](figures/diagrams/s20_defect_ladder.png)

!!! intuition "The one-liner"
    Change the pipeline, freeze the model, split, and seeds — so the only thing that *can* explain the gap is the pipeline.

**Verify.** The defect-by-defect ladder and which arm carries which rung live in §20 of the Explainer and in the diagram source `note/diagrams/s20_defect_ladder.mmd`. The frozen split (490/105/105, stratified by RC presence, seed 42) is asserted at data-load time and reproduced in `scripts/compute_dossier_facts.py`.

!!! gotcha "Watch out — a *bundle* is one variable only if it always moves together"
    The pipeline change is three coupled edits (data, loss, checkpoint rule). That is legitimately "one variable" for an A/B **only because they are never varied independently** — I do not claim to isolate the loss *from* the sampler *from* the selection rule. The bullet's causal claim is at the level of "the pipeline," not "the DiceCE loss specifically." Anyone who wants per-defect attribution needs an ablation, which this A/B does not provide.

!!! example "Interview question"
    **"How is bundling several changes into one arm a *controlled* experiment — isn't that many variables at once?"**
    It is controlled at the resolution the claim is made: **pipeline vs. model**. The three edits (data handling, loss, checkpoint-selection) are treated as one variable because they always move together and are never varied independently, while the genuinely tempting confounders — architecture, data split, and seed protocol — are each held fixed. So the experiment cleanly attributes the delta to "the pipeline as a whole." What it deliberately does *not* do is attribute the delta to any single defect; that would require a per-defect ablation, and I am careful not to over-claim that resolution.

### "to isolate cause from model"

**Claim.** *"to isolate cause from model."* The purpose of freezing the architecture is to make the observed gap **unattributable to the network** — to separate the *cause* (pipeline) from a possible *confound* (a better model).

**What it means — the byte-identical network is what licenses the causal claim.** Both arms instantiate the *same* network: a MONAI `UNet`, `spatial_dims=3`, `in_channels=3`, `out_channels=5`, channels `(16, 32, 64, 128, 256)`, `num_res_units=0`, dropout `0.1` — **1,983,069 trainable parameters**, identical down to the parameter count on both tracks. Because the function class is fixed, the network cannot be the reason Track B wins.

**Evidence and the counterfactual.** The whole causal argument is a counterfactual: *if Track B had also been given a stronger network*, then the improvement would be jointly caused by architecture **and** pipeline, and the two contributions would be **confounded — unattributable**. The bullet would then have to read "a better pipeline *and* a better model did better," which is not a finding, just a bigger bet. By holding the 1,983,069-parameter network byte-identical, the only thing left that *can* explain a difference is the pipeline. (The magnitude of that difference — held-out mean-fg Dice **0.349 → 0.670**, Δ = **+0.321 ± 0.013** over 3 seeds — is defended in §4; here the point is only that it is *attributable*.)

!!! intuition "The one-liner"
    Same net, same split, same seeds — so a difference in output is, by construction, a difference the pipeline made.

**Verify.** The identical architecture and the 1,983,069-parameter count are printed at model-build time on both tracks and tabulated in `reports/figures/dossier/param_breakdown.png`; the count is recomputed in `scripts/compute_dossier_facts.py`. That both arms share one split and one seed protocol is asserted in the data module and reproduced in the same script.

!!! gotcha "Watch out — 'byte-identical network' is a claim about the *architecture*, not the weights"
    The two arms share an identical *function class and initialisation protocol*, not identical learned weights — the weights necessarily differ because the training signal (loss, sampling, data) differs. That is the point: same net, different pipeline, different weights *as a consequence of* the pipeline. Do not overstate it as "identical models."

!!! example "Interview question"
    **"How do you know it's the pipeline and not the model?"**
    Because the model is the one thing I refused to change. Both arms are the exact same MONAI 3D U-Net — **1,983,069 parameters**, identical channels, strides, and dropout — trained on the same fixed 490/105/105 split under the same 3-seed protocol. The only difference between the arms is the data-and-training pipeline (labels, normalisation, sampling, loss, checkpoint rule). Under those conditions the Track A → Track B gap has no architectural degree of freedom to hide in. The counterfactual makes it concrete: had I *also* upgraded Track B's network, the delta would be confounded by architecture plus pipeline and I could not claim either as the cause — which is precisely the mistake this design exists to avoid.
